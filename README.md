## 製品概要

### 背景(製品開発のきっかけ、課題等）

きっかけは、チームメンバーが一人暮らしで室内干しをしていたときの経験です。
洗濯物がなかなか乾かず生乾きのにおいが残ったり、着たいタイミングまでに乾かず着られなかったりしました。

室内干しをするのは雨の日だけではありません。
花粉や黄砂が飛ぶ時期や、寒くて外に干すと凍ってしまう日も、洗濯物は室内に干すことになります。
室内干しの悩みを解決できれば、生活の質が上がると考えました。

洗濯物を早く乾かすために、私たちは空調に着目しました。
室内干しが乾きにくいのは、部屋の空気が洗濯物の水分を受け取りにくい状態になっているためです。
エアコンで室内を乾燥に適した環境に整えれば、室内干しでも早く乾かせます。

ただし、家にいるときは、乾燥だけを優先するわけにはいきません。
外出中は乾燥を最優先にできますが、在室中は暑すぎたり寒すぎたりしない快適さも守る必要があります。
室内干しくんは、室温や湿度などの室内の状況と、外出・帰宅の連絡による在室状況をもとに自律的に空調を制御し、乾燥と快適さの両方を考えた環境に調整します。

### 製品説明（具体的な製品の説明）

室内干しくんは、Raspberry Pi に接続した温湿度センサーと赤外線送信機で、自宅のエアコンを洗濯物の乾燥に合わせて自動で運転するシステムです。
ユーザーが行うのは、LINE 上での洗濯物の登録と、外出・帰宅の連絡だけです。

#### 使い方

1. LINE のリッチメニューから、干した洗濯物の写真または、エアコンから見た洗濯物の位置（左・正面・右）を送ります。
2. 「いってきます」を押すと、室温・湿度をもとにエアコンの運転モード・設定温度・風量・風向きを決めて、赤外線で送信します。
3. 乾燥の進み具合を推定し、乾き終わったらエアコンを止めて LINE に「洗濯物の乾燥が完了しました。」と通知します。
4. 「ただいま」を押すと、在室中の快適さも考慮した運転に切り替えます。

### 特長

#### 1. 乾きやすさを数値化して、エアコンの運転を自動で選ぶ

室温・湿度から飽差（VPD）を計算し、洗濯物の乾きやすさを数値で表します。
冷房・暖房・除湿の各モードと設定温度・風量の候補ごとに、この先の室温・湿度の変化をシミュレーションし、乾燥の速さが最も良い運転を選びます。
あわせて、乾き終わるまでの推定残り時間も算出します。

#### 2. 外出中は乾燥優先、在室中は快適さとのバランス

LINE の「いってきます」「ただいま」ボタンで在室状態を切り替えます。
外出中は乾燥を優先し、在室中は快適な室温から離れすぎない運転や、風量を抑えた運転を選びます。

#### 3. LINE だけで完結する操作と、洗濯物に向けた送風

専用アプリは不要で、普段使っている LINE のボタンを押すだけで操作できます。
洗濯物の位置を登録しておくと、エアコンの左右の風向きを洗濯物に向け、上下の風向きも運転モードに合わせて調整します。
乾燥が終わると LINE に通知が届くため、外出先からでも状況が分かります。

### 解決出来ること

- 室内干しの乾燥時間を短くし、生乾きのにおいを防ぎます。
- 洗濯物が乾くタイミングが分かります。
- エアコンの運転モードや温度を自分で考える手間をなくします。
- 乾いたら自動で止めるため、エアコンのつけっぱなしによる無駄な電気代を減らします。
- 外出中でも、洗濯物が乾いたかどうかを LINE で確認できます。

### 今後の展望

- 洗濯物の写真から量や生地を推定し、乾燥時間の予測に反映する
- 実際の乾燥時間を記録し、乾燥モデルの係数を家庭ごとに調整する
- 扇風機との連携
- 洗濯プロセスの自動化

### 注力したこと（こだわり等）

- 乾燥の進み具合を勘ではなく、飽差（VPD）に基づくモデルで推定し、冷房・暖房・除湿の候補を同じ基準で比較できるようにしました。
- 命令する温度を16〜28℃に制限し、在室中は乾燥中でもエアコンを止めないなど、安全側に倒した制御にしました。
- Raspberry Pi の標準ドライバー（DHT11 / LIRC）を TypeScript から直接扱い、追加のネイティブライブラリなしでセンサーと赤外線を使えるようにしました。
- 実機のエアコンで記録した赤外線信号をそのまま送れるため、メーカーごとの通信方式を解析しなくても操作できます。
- LINE のリッチメニューをタブで切り替え、ボタンを押すだけで操作が完結するようにしました。

## 開発技術

### 活用した技術

#### API・データ

- [LINE Messaging API](https://developers.line.biz/ja/docs/messaging-api/)（Webhook、リッチメニュー、Flex メッセージ、プッシュメッセージ）
- 飽差（VPD）に基づく乾燥時間の推定モデル

#### フレームワーク・ライブラリ・モジュール

- TypeScript / Node.js 22
- pnpm workspaces（モノレポ）
- [Express](https://expressjs.com/)
- [LINE Messaging API SDK for Node.js](https://github.com/line/line-bot-sdk-nodejs)
- [Vitest](https://vitest.dev/)
- `ir-ctl`（v4l-utils）
- GitHub Actions（単体テストの自動実行）

#### デバイス

- Raspberry Pi 4
- DHT11 温湿度センサー
- 赤外線受信モジュール・赤外線 LED
- 家庭用エアコン

### 独自技術

#### ハッカソンで開発した独自機能・技術

- **乾燥運転の計画アルゴリズム**（[packages/core/src/drying/](packages/core/src/drying/)）
  - 室温・湿度・在室状態・乾燥の進み具合を入力に、次の運転（モード・設定温度・風量）と乾燥完了までの推定時間を返します。
  - 運転候補ごとに室内の温湿度の変化を15分刻みでシミュレーションし、乾燥の速さと快適さの重み付きスコアで比較します。
  - 詳細は [packages/core/README.md](packages/core/README.md) にまとめています。
  - 主なコミット: `c754e70`（VPD による乾燥制御と運転判断）、`3b11933`（乾燥完了予測と運転評価の修正）
- **洗濯物の位置に合わせた風向きの決定**（[packages/core/src/ac-wind-direction.ts](packages/core/src/ac-wind-direction.ts)）
  - 主なコミット: `96d60bb`
- **Raspberry Pi での赤外線送受信と温湿度取得**（[packages/sensor/](packages/sensor/)）
  - Linux の LIRC と IIO ドライバーを TypeScript から扱い、GPIO 番号からデバイスを自動で選びます。一時的な読み取りエラーはリトライします。
  - 主なコミット: `3f80cf0`（赤外線送受信）、`86c0f9f`（DHT11 の温湿度取得）、`23e28d6`（リトライ）
- **LINE Bot**（[packages/line/](packages/line/)）
  - タブ付きリッチメニューとポストバックで操作を受け付け、乾燥完了をプッシュメッセージで通知します。
  - 主なコミット: `80bf2bc`（リッチメニュー）、`b0bdf80`（乾燥完了通知）
