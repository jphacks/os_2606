# 6時間の運転シミュレーション

現在の予測ロジックで6時間分の運転を試算します。標準設定では15分ごとに温湿度と乾燥進捗を更新し、1時間ごとに運転を選び直します。乾燥進捗が1に達したら停止し、残り時間の室内環境も計算します。

## LINEから実行

「洗濯物」メニュー右端の「6時間の運転計画」を押します。現在のセンサー値、設定済みの外気温湿度、実機で送信可能な設定を使って、冷房・暖房・除湿・停止、設定温度、風量、区間終了時の室温・湿度・乾燥進捗を返信します。

乾燥中は進捗と在宅・外出状態を引き継ぎ、未開始なら在宅・進捗0から試算します。試算によって実機を操作したり、乾燥開始・終了予定時刻・通知先を変更したりすることはありません。

ボタンと新しい画像を反映するには、通常のデプロイで行われるメニュー再登録が必要です。手動で登録する場合は次を実行します。

```sh
pnpm build
pnpm setup:rich-menu
```

## ローカルのプログラム

センサーやLINEの認証情報なしで実行できます。

```sh
pnpm simulate:drying
pnpm simulate:drying --input examples/drying-simulation.json
pnpm --silent simulate:drying --input examples/drying-simulation.json --format json > simulation.json
```

入力は[環境JSONの例](../examples/drying-simulation.json)を編集します。`presenceMode`は`home`（在宅）または`away`（外出）、`dryingProgress`は0〜1です。`comfortTemperature`と`dryingProgress`は省略可能で、24℃・進捗0として計算します。

入力を省略すると、室温24℃・湿度70%、外気18℃・湿度60%、在宅、快適温度24℃から開始します。CLIでは既定の運転候補を使い、LINE実行時は実機の対応設定による絞り込みも適用します。

テキストは開始からの経過時間を使います。JSONの`steps`には区間の開始・終了分、運転、区間末尾の温湿度と進捗を記録します。各`decision.estimatedDryingHours`はその評価区間の開始時点で、選んだ運転を継続した場合の予測です。`completedAtMinute`は再計画を含む6時間の試算で進捗1になった時刻で、完了しなければ`null`です。JSONで表せない`Infinity`の予測時間も`null`で出力します。

## 前提

外気温湿度と在宅・外出状態は6時間固定します。係数は実測で校正されていないため、表示は比較用の参考値です。将来の運転を予約せず、実際の乾燥時間や完了を保証しません。実際の乾燥サイクルには、今回の試算のような定期的な再計画は追加していません。
